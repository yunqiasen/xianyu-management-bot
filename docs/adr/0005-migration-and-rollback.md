# 单账号交接与增量对账回退

旧数据由SQLite映射到原版MySQL模型，迁移覆盖账号配置、聊天、商品、订单、库存和待确认状态；临时连接与运行锁重新建立。先做一致性备份、重复导入演练和字段/关联核对，再在单账号独占条件下停止旧执行权、补齐增量并交给新系统。

回滚保留版本回退点，但不以旧数据库覆盖切换后的新消息、订单及发货事实：先停新执行权、核对增量，再恢复旧执行权。代价是交接窗口和对账工具，收益是回滚不变成业务数据倒退；日志保留周期、试跑时长等数值仍在规格里明确，当前没有数据清理或迁库动作。

确认依据：用户总体同意备份演练、单账号切换、核对新增数据的回退方案。

本记录描述已接受的设计方向，不表示代码已实现或已通过业务验收。
