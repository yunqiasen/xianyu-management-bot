# 持久发货阶段与仅补确认

卡密发送和平台发货确认是两个独立结果；任一请求超时都可能只是回执丢失，直接重新发货会重复出库。卡密预占、发送与待确认阶段持久化：已发卡但平台确认失败时仅补确认，结果不明时先核实，进程重启不把订单当成全新任务。

这一决定以更多状态和对账流程换取可恢复性，不把内存锁或请求返回成功当作交易完成证据。默认回复、聊天发送同样区分提交、确认、失败和待核实，但不与订单发货状态混为一套业务状态。

确认依据：完整方案的订单防重、卡密预占和“只补确认不重复发货”已向用户展示并获总体同意。

本记录描述已接受的设计方向，不表示代码已实现或已通过业务验收。
