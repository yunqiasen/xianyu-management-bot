# 监控可靠性增强

对应 DEV-46 / AT22–24。复用原版监控页、账号执行方和通知队列；`XYMB_ENABLE_MONITOR_V2` 默认false，显式开启后才采用增强流程。新建任务默认停用、5分钟/1页，旧配置不自动激活。

## 接线与持久状态

启动DDL注册监控四表和迁移，账号命令 `monitor_search_page` 已注册。监控采集代次与账号执行代次分别检查；外发仍经同一账号固定代理和共享预算，不另建浏览器、登录或消息连接。

- state：查询指纹、采集代次、地区、租期、完整基线。
- pages：任务、账号、关键词、页码、代次、查询指纹和请求ID全部匹配；局部失败保留检查点。
- observations：任务/查询/商品价格修订，回升后再下降生成新事件。
- events：持久发现事实及通知身份；通知失败不删除发现记录，重启不重复入队。

只有HTTP、平台业务、响应结构和全部配置分页成功才完成一轮；真实空页有效，缺页/错误不冒充空结果。首次完整基线不通知存量；重建基线是明确操作。旧代次响应只记录过期，不覆盖新结果。

增强结果不写旧自动下单/私信采集表。任务级代理、下单或私信与账号策略冲突时保留原值并提示处理；所有选定账号暂停时等待，不抢占登录或更换出口。

## 页面与验证

`GET/PUT /product-monitor/listing-tasks/{task_id}/reliability` 沿原任务归属。面板展示基线、页错误、事件及逐渠道投递阶段；地区变更使基线失效，关闭增强开关时不查候选表。

`tests/monitor/` 覆盖空/错/缺页、身份错配、乱序、重启、价格回升再降、通知分离、旧路径关闭回归、API及Chromium。`tests/dispatch/test_monitor_wiring.py` 检查实际命令链；`tests/integration/test_candidates_mysql.py` 验证MySQL重启、约束和事件身份。唯一事件身份使用MySQL 8 `utf8mb4_0900_bin`，保留大小写和尾空格。

参考LENKIN的完整基线、请求页关联和持久去重；未照搬截断存量索引或按回调顺序猜价格的做法。固定提交与许可证见 [来源](../SOURCES.md)。本地集成回归不代替真实账号监控及发布观察。
