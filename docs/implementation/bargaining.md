# 议价语义与长会话历史

对应 DEV-45 / AT21。`XYMB_ENABLE_BARGAINING_V2` 默认false；复用P2共享历史、原意图提示和六协议网关，不另建聊天存储。

## 行为

- 普通询价使用价格提示，但不计让价轮数；明确买家还价/让价才计数。“评价”、单字价/刀、刀具咨询、优惠功能设置和否定砍价有反例。
- 计数来源为已确认的买家平台文本事件；按账号、会话、事件ID持久唯一。缺事件ID只记诊断，不编造新身份。
- 展示窗口之外的保留事件分批对账，避免100条窗口截断计数。存储正文哈希而非另一份聊天正文。
- 议价事实先提交再调用模型；失败、重放、重启或清理展示历史不清除已确认次数。MySQL并发用唯一键和当前读裁决重复，不靠内存锁。
- 历史按最新完整往来整组裁剪，包含人工承诺；先扣系统、商品、限制与当前问题预算。最新完整组本身过大时返回明确预算错误，不静默截正文。

`xy_bargaining_events` 已进入公共导出及启动迁移；MySQL 8的 `utf8mb4_0900_bin`（NO PAD）区分大小写、尾空格，不级联删除业务事实。整库备份纳入该表；回退时旧端没有等价字段的事实保留在加密增量包并列为待对账，不凭旧AI price记录推算次数。

## 诊断与验证

`GET /ai-reply-settings/{account_id}/bargaining-diagnostics` 按账号归属输出白名单字段：次数、采用/裁剪/人工条数、事件范围和错误阶段；不返回原快照或正文。原AI面板已挂载，关闭开关时隐藏并返回 `candidate_enabled:false`。

`tests/bargaining/` 从保存配置、正式回复、共享历史到真实本地HTTP、诊断API和Chromium；`tests/integration/test_candidates_mysql.py` 验证真实MySQL并发、身份及重启。默认关闭的原AI与回复回归由同一完整验证器收集。

参考shaxiu意图、轮数及上下文结构，未沿用单字“价”、旧ASC/LIMIT窗口、仅chat_id隔离和计数随历史清理的行为。来源及许可证见 [来源](../SOURCES.md)。已丢失的旧历史保持缺证据状态；正式模型、消息及长期运行另行试跑。
