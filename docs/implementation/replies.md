# 回复、人工接管与连续历史

对应 DEV-11–15、20–22。复用原聊天和规则页面，统一调用账号执行方；不再由聊天管理页建立第二条平台登录。

## 决策顺序

先检查账号状态、会话人工暂停、黑名单及入站过滤。

- 迁移账号 `legacy`：商品专属→商品关键词→通用关键词→商品/账号默认→AI。
- 新账号 `ai_first`：商品专属→商品关键词→通用关键词→AI→商品/账号默认。
- 商品专属与商品默认分开存储。决策区分未匹配、正文、明确跳过、错误；启用的空回复、只回一次已用完和人工暂停结束链路。
- 只回一次先事务预占，平台确认后消耗；明确未发送释放，未知保留。迁移的旧名额保留对应作用域。
- 过滤包含/精确/有界简单正则，支持来源和商品范围，动作区分通知、跳过AI、跳过回复、暂停及通知抑制。通知动作本身不阻止正文。可选同用户全部现有及未来账号，暂停分钟独立设置，合法0与继承账号值分别处理。
- 生成后及每次发送前重读规则和暂停；中途人工接管阻止后续片段，内部控制标记不发给买家。

## 历史与回执

原始买家、人工、机器人消息保存在同一账号＋会话历史。防抖合并保留原事件关联，不吞订单事件。平台身份去重与缺身份的有界指纹分开；同正文不是永久去重键。

人工/程序/自动发送具有持久操作ID，阶段为 submitted / confirmed / failed / unknown。重复提交返回原任务；回执及平台读取用于核实未知结果，缺少可靠证据时保持待核实。人工发送后的暂停保留合法0，其他账号同名会话不受影响。

实时事件采用提交水位和游标；重连补拉、旧版本抑制、过期游标刷新快照。MySQL回归检查并发提交、回滚和重开连接，不把自增ID本身当提交顺序。

## 图片与黑名单

图片按用户和内容哈希管理，校验格式/大小/像素；引用覆盖关键词、默认/专属、素材和发布快照。原上传接口返回有归属的预览地址；共享卷和迁移要求见使用说明。在用资源先查引用；清理元数据与物理文件回收分开。

平台名单同步、聊天拉黑与列表复用同一归属和执行方；同步只删除有明确平台结果的成员，不将一次不完整查询当完整名单。回复屏蔽与已付款订单履约规则独立。

## 验证

`tests/replies/` 覆盖规则、名额、回复链及原始事件；非标准文件 `api_suite.py`、`blacklist_suite.py`、`keyword_roundtrip_suite.py`、`live_ai_suite.py`、`mysql_stream_suite.py` 均由完整验证器收集。六种协议×两种策略包含正常和错误场景。`tests/dispatch/` 验证实际回执和执行方；`tests/runtime/asset_privacy_suite.py` 验证图片文件归属及退出撤销。

已注册的增量表由 `upgrade_fork_schema` 在启动DDL门内维护，HTTP请求不建表。真实平台消息及长时间断线观察单列发布验收。
