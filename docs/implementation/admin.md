# 后台身份、通知、日志和恢复

对应 DEV-32–38。复用原后台路由及 React 页面；公共模型、启动迁移、跨服务认证和通知队列已接入，不再保留领域代理的接线待办。

## 身份与管理

- 注册、密码/邮箱验证码登录、令牌刷新、登出和重置密码使用真实用户状态及 `token_version`。注册开关同时约束注册与注册码发送；短密码或注册关闭不先消费验证码。
- 用户名和IP分别按15分钟窗统计，缺省阈值5/20次、锁定15分钟。邮箱别名归一到同一后台身份；管理员只解锁选定维度，配置采用版本检查。
- API、文件、截图和实时入口重查用户状态/角色；旧令牌、降权和停用及时失效。后台身份与闲鱼账号凭据分开。
- 经营总览以明确时间窗、时区、付款/退款状态和Decimal金额统一明细、趋势及汇总；账号数量不代替业务可用数量。

## 通知

`NotificationEvent → 模板快照 → 各渠道 NotificationDelivery`，业务事实和通知受理分开。支持QQ OneBot、钉钉、飞书、企业微信、Bark、Telegram、PushPlus、Webhook、邮件；每种渠道单独校验配置及业务回执。

- 调度服务启动已注册通知worker；自动调度关闭时不主动投递。
- 同账号/类型/故障代次15分钟合并告警，恢复单独一次。账号状态事件已接该链。
- 明确未受理最多额外三次，60/300/900秒；unknown不自动重投。
- 模板按用户/事件保存，允许变量、缺省、预览和恢复默认明确。旧通知事件和变量按兼容映射保留，错误回退脱敏摘要，不夹带完整凭据。

## 日志和审计

关联ID贯穿Web、消息、调度与外部请求。日志页支持服务/账号/关联ID、分页、导出、缺服务提示；普通日志和异常先脱敏。

- 新配置的运行文件保留30天；旧显式值保留。超期文件进入归档，结构化日志只归档30天前明确终态。
- `AdminAuditArchive` 保存180天前已完成的登记管理动作，保留来源ID、操作者及原时间；备份调度执行原子归档。unknown/restoring、未知动作及在途引用继续在线。
- 日志归档页可切换运行日志/操作审计；重复维护幂等。业务历史、防重事实和待核实关联不随普通日志清理。

## SQL.gz备份与保护点

现有备份调度使用UTC、一致性只读快照和InnoDB检查，导出表结构、原始值、约束及清单。二进制、NUL、微秒和合法零主键有往返验证；非事务表报失败，不伪造一致性备份。

`BackupVerificationService` 执行文件校验或实际恢复：目标由后端 `ADMIN_RESTORE_DATABASE_URL` 给定，必须另一MySQL实例、`xymb_restore_`前缀空库，检查server_uuid而非只看地址。恢复后校验行数、外键和业务关联，并还原连接会话设置；失败保留隔离证据，不写当前库。

保护点API/UI在设置前重新检查状态、文件及SHA256；保护操作与清理锁同一父备份，幂等且留审计。验证历史返回最近20条及全部保护点。日7份、周4份、最近恢复点及保护点分别保留；新备份没有匹配哈希的真实恢复记录时不淘汰旧文件。

## 数据操作

表/操作白名单、归属和敏感字段掩码。仅通知配置开放关联删除，其余业务表只读。删除需要5分钟有效预览、明确DELETE确认、与当前配置匹配且实际恢复过的备份；并发变化使预览失效，事务失败不留下半次删除。

## 验证入口

`tests/admin/` 覆盖认证生命周期、权限、统计、逐渠道通信、模板、日志/审计归档、保护点、数据操作；`test_backup_roundtrip.py` 从正式调度导出SQL.gz并恢复到第二MySQL。`tests/runtime/` 补文件/实时入口撤销和错误脱敏。

`tests/admin/browser_flow.py` 使用真实Chromium、组件、API、MySQL和隔离恢复，操作定向解锁、配置、归档分类、保护点和删除预览。组件harness不等于完整后台视觉验收；正式邮件、通知渠道与平台业务另列发布证据。接口见 [API](../API.md)，恢复操作见 [使用说明](../OPERATIONS.md)。
