# 发布检查器与验证器

对应 DEV-43/44/47。工具只验证证据，不发起提交、推送、部署或生产账号切换。

## 完整工程回归

`tools/verification/run.py` 在独立进程依次运行每个领域、特殊命名suite、前端lint/build、组件行为及Chromium场景。真实MySQL/Redis通过显式私有环境提供，订单竞争使用临时schema；SQL恢复使用第二MySQL实例。

输出目录必须新建且在源码外。`results.json`记录HEAD、包含未跟踪文件的源码指纹、开始/结束、每套命令/退出码/测试数/跳过数/耗时和总结果。零测试、跳过、超时、源码变化或未收齐套件都会失败。`--suite`只算定向验证，`--plan`只展示命令。

## 候选检查器

`tools/release` 的 `init` 产生全部pending清单，`check` 分 code / trial / acceptance 三道门。固定规格、49组能力矩阵和19项差异处置随仓库保存；新检出不依赖某台主机的`.scratch`目录。

检查内容：

- 固定基线祖先、增强分支、干净已提交源码、初始旧标签保持原指向；检查前后再次读Git状态。
- 候选/提交/范围/入口一致；实现与测试文件哈希及真实行范围；回执及附件哈希、唯一ID和路径边界。
- 非空执行、零失败/跳过；演示回执与函数探针不冒充集成证据。
- 回归、前端构建/操作、候选镜像、类型检查、契约、MySQL/Redis、迁移、SQL恢复、增量回退、文档、来源、总审查及恢复点。
- commit/push/deploy三份独立许可；真实单账号十二类场景、至少48小时、实际版本/镜像/检查点及无严重未解决问题。

第一候选排除P5；增强候选再要求AT21–24和DEV45/46。两者都不假定另一候选已部署。哈希只证明一致性，附件业务含义和许可仍需人工审查。

`tests/release/test_gate.py` 使用临时Git和合成回执验证正确通过/失败，包括新检出、自测源码变化、标签、输入篡改、缺场景、跨账号/窗口及47:59:59小时边界。测试正向结果不是实际发布证据。
